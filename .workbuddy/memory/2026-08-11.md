## 教训 / 经验（跨项目可复用）
- **file:// 下 3D 模型**：CORS + ESM + 纹理全失败 → 烘焙 GLB→BufferGeometry（位置/法线/索引 Int16 + base64），atob 解码即可，零运行时依赖。比打包 base64 GLB 小 40×。
- **对象池的两层 alive**：业务 alive（"是否在逻辑上活着"）和池 _in（"是否在 active 列表里"）必须分离，否则一处提前置 false 会导致池无法回收 / 链式引用。
- **范围伤害必须迭代而非递归**：splash/爆炸/分裂 这类二次作用，要么队列化迭代，要么先置 dead 标记 + 同帧保护。
- **空间哈希负坐标**：用 `(cx+OFF)*1024+(cz+OFF)` 比 XOR 哈希安全得多，OFF 给定 ≥ 坐标范围/cell。
- **截图前清理副作用**：要截某状态的干净画面，先 `Loot/Particles.clear + state reset`，否则其他系统的"输入流"会污染画面。

## 修复：子弹发射位置不对（用户："子弹发射位置不对宝宝"）

### 根因
上次「优化建模」换成 Kenney 模型后，`tools/bake_models.mjs` 对所有飞船用了 `rot:[0,π,0]`，**在烘焙期就把机头旋到 +Z**（与游戏约定 group.rotation.y = yaw 一致）。
但 `build/p2_core.js` 的 `Gfx.meshYaw` 还残留旧 Poly Pizza 模型的朝向修正 `{ fighter: -π/2, hauler: π/2 }`。
结果：玩家 `Gfx.ship('fighter', ...)` 被额外转了 -π/2，机头实际指向 `yaw - 90°`，子弹却朝 `yaw` 飞 → 视觉上子弹从机身**侧面/旁边**冒出来。

### 修复
- `build/p2_core.js` `Gfx.meshYaw.fighter`: `-π/2` → `0`（烘焙后机头已是 +Z，无需再转）
- `hauler` 已无引用，保留旧值无害（注释说明已弃用）
- 僚机(`wing_a/wing_b`)、敌人(`enemy_*`)、BOSS 部件在 meshYaw 中**无条目**(默认 0)，且烘焙时已带 rot π，本来就正确，不动

### 验证
- `tools/build.mjs` 重新打包 → index.html 111.5 KB
- `tools/check.mjs` 29/29 通过，0 控制台报错
- `tools/shot_nose.mjs`（新）：覆盖 `World.updateCamera` 定住摄像机到玩家正侧方（-16,5,4 看 0,1,5），让 +Z 指向屏幕右侧
  - 截图清晰显示：飞船机头朝右，子弹（青色光束）从机头正前方射出向右飞 ✓

### 教训
**建模替换后必须同步检查 `meshYaw` 表**。烘焙脚本里的 `rot` 旋了多少，`meshYaw` 就得相应归零（或反向）。把约定改成「烘焙时统一把机头旋到 +Z，运行时 meshYaw 全为 0」会更不容易踩坑——下一步可以考虑彻底清空 meshYaw 表。

## 优化：加背景音乐 + 静音按钮（用户：「有点音乐之类的就更好了」）

### 现状发现
代码里 `build/p3_world.js` 已有较完整的 `Audio2` SFX 模块（`shoot/kill/levelup/hurt/dash/boom/bossWarn/win/lose/gem/tone/noise`），且**所有 SFX 钩子已全部接好**（p4 player 受伤/冲刺、p5 开火/导弹/激光、p6 击杀/拾取、p7 BOSS 警告/爆炸、p8 升级/胜负）。唯一缺的是**背景音乐循环**和**静音 UI**。

### 改动
1. **Audio2 双总线架构**（`p3_world.js`）：拆出 `sfxBus`（0.9）和 `musicBus`（0.42），都接 `master`（0.5）。`master` 设 `_mg=0.5`，静音时统一拉到 0。`_env` 改为接到 `sfxBus`。`init()` 预生成 0.4s 白噪声 buffer 给鼓点复用。
2. **背景音乐合成器**（`p3_world.js` Audio2）：
   - `musicBars`：4 小节 vi-IV-I-V（A 小调），每小节 `bass / arp / lead` MIDI 音符
   - `startMusic()` / `stopMusic()`：用 setInterval(25ms) + lookahead 0.14s 的标准调度模式，每 16 步一小节、共 64 步循环（122 BPM，约 8s 一圈）
   - `_step()` 编排：低音根音（4 分音 + 八分回弹）、和弦琶音（八分方波+12oct）、稀疏旋律（锯齿）、kick（正弦 pitch 150→45）、hat（高通噪声）
   - `_at / _kick / _hat` 都接 `musicBus`
3. **静音切换** `toggleMute()`：用 `setTargetAtTime` 平滑压住 `master` + `musicBus`，0.05s 时间常数
4. **HUD 接线**（`p8_game.js`）：`HUD.init` 加 `btnSound` 引用 + 点击监听（调 toggleMute 并切换 🔊/🔇 图标 + `.off` class）。`Game.start` 调 `Audio2.startMusic()` 并同步图标；`Game.over` 调 `Audio2.stopMusic()`
5. **UI**（`p1_shell.html`）：`#topRight` 末尾加 `<div class="chip btn-snd" id="btnSound">🔊</div>` + CSS（`pointer-events:auto` 突破 `#top` 的 none，hover 青色发光，`.off` 灰化）

### 经验
- **顺序敏感的构造函数**：当一个系统的 reset 依赖另一个系统的当前状态（比如 Progress 依赖 Player.cfg），必须严格保证依赖者后初始化。菜单/重开场景下尤其危险（首次对，重复开局后全错）。

- **verify 用 expect-map 而非硬编码**：写 expect map 而不是"如果 shipIdx 是 i 就期望 X"，便于复用且文档化预期行为。

## 建模优化：无人僚机 + 光刃 真 3D 模型（用户：「无人僚机和光刃之类的没建模，优化」）

上一轮 Request B 引入了「无人僚机」（drone）和「环绕光刃」（orbit blade），但仍用 `ConeGeometry` 原始体（无人僚机：amber 锥刃；光刃：cyan 锥刃）。这次给两件都换上**离线烘焙的真 3D 模型**。

### 1. 零依赖 GLB 生成器（`tools/make_models.mjs`，新增）
- 不引入 three.js / npm 包，纯 Node 写一个 `tools/make_models.mjs`：
  - `addTri/addQuad`：法线由 `(b-a)×(c-a)` 现算，与发射顺序一致，避免 winding 不匹配导致 Lambert 面被剔除；
  - `box(w,h,d)` / `cyl(r,h,seg)` / `rotateY` / `translate` / `merge`：基础图元生成器；
  - 手写一个轻量 **GLB 容器打包器**（12B header + JSON chunk + BIN chunk，4 字节对齐，按 bufferView/accessor/buffers 顺序拼装），产出可直接喂给 `bake_models.mjs` 的合法 GLB。
- 生成的模型：
  - **drone.glb**：4 部件 = 机身 box(0.42×0.20×0.50) + 2 交叉机臂 box(0.70×0.07×0.09) 旋 ±45° + 4 旋翼（每颗 cyl(0.14,0.05,10) + box(0.30×0.025×0.05) 桨叶）+ 传感眼 box(0.13×0.11×0.13)（emissive）。530 顶点 / 256 三角 / 16.9KB GLB。
  - **blade.glb**：沿 +Z 的**锥形双刃**（4 棱 14 段环向 lerp 收口至尖端），附 **十字护手** box(0.34×0.045×0.09) + **发射座** box(0.13×0.15×0.13)。177 顶点 / 142 三角 / 11.2KB GLB，emissive 青色。
- 朝向约定：blade 沿 +Z（与旧 ConeGeometry `rotateX(π/2)` 后的指向完全一致），rotation.y = a 时绕切向扫荡，**不需要任何运行时补偿**。

### 2. 烘焙接入（`tools/bake_models.mjs`）
- JOBS 末尾新增：`{ key:'drone', file:'drone.glb', size:0.7, rot:[0,0,0] }` 与 `{ key:'blade', file:'blade.glb', size:1.3, rot:[0,0,0] }`。
- `node tools/bake_models.mjs` → `assets/meshes.js` 119KB（含裁剪/Int8 法线），drone 4 部件 440v/256t，blade 1 部件 177v/142t。

### 3. 运行时渲染器（`build/p2_core.js` + `build/p5_weapons.js`）
- **Gfx.drone(tint, scale)**：复用 ship() 的部件循环（Lambert 0.5 原色 + 0.5 阵营色混合 + emissiveIntensity 0.2），每部件加 BackSide 1.06 黑壳描边；4 颗旋翼位置 [±0.248, ±0.248] 放 additive 阵营色小球当导航灯；尾部 `Gfx.thruster(0.10, -0.30, {opacity:0.5, core:0.6})` 微推进器。返回 **Group**（不是 Mesh），可整体位置/旋转。
- **Gfx.blade(tint)**：返回单个 Mesh（`.material.opacity` 可呼吸），BufferGeometry + 加法青色 MeshBasicMaterial（depthWrite false / double side / fog false），保留能量武器观感。
- `Weapons.init()`：把原本的 `new THREE.ConeGeometry(...)` 双循环换成 `Gfx.drone(0xffcc33, 0.85)` / `Gfx.blade(0x8ff0ff)`。
- `Weapons.update()` 无人机分支：删掉 `d.mesh.material.opacity = ...`（Group 无 `.material`），保留 `position / rotation / visible`。
- **零回归**：僚机沿用已烘焙 ship key（wing_a/wing_b/enemy_*/hauler），不在本次改动范围。

### 经验
- **零依赖 GLB 生成器**对小型武器/装饰件完全够用：不需要 three.js + GLTFExporter + npm，几何用现算叉积法线，GLB 容器手写 70 行打包（header 12B + JSON/BIN chunk + 4 字节对齐）。比拉三个 npm 依赖省时。
- **法线叉积必须用 `(b-a)×(c-a)` 顺序**：法线方向自动锁定到发射顺序 → 与 winding 一致，Lambert 不会被自剔除。手写 box/cyl 时这点一不注意就翻车（面变透明），但只要坚持叉积公式就稳。
- **bake 归一化是免费的体积控制**：`size: 0.7` / `size: 1.3` 由 bake 工具把任意尺度归一到目标最长边，几何构造可以放飞，最后由烘焙阶段统一切齐。
- **Group vs Mesh 边界**：原 drone 用 Mesh 做 `.material.opacity` 呼吸；改成 Group 后必须删掉 opacity 操作，改用可见性 toggle。视觉上"呼吸感"靠自动开火粒子和导航灯 additive 闪烁就够了。
- **机型渲染器分家**：把 `Gfx.drone` 和 `Gfx.blade` 与 `Gfx.ship`/`Gfx.enemyShip` 并列，但 drone 不需要 canopy/ground glow（飞行体），blade 不需要 outline（加法材质），都是按"应用场景"裁剪过的最小集合。
